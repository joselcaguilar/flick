# P0-05 — Home Assistant WebSocket client spike

Status: implemented against `crates/flick-ha` mock HA. Real LAN round-trip is **pending** the owner's long-lived token and URL.

## Protocol details relied on

- Endpoint: `/api/websocket`, using `ws` for `http` and `wss` for `https` bases.
- Handshake:
  1. server sends `auth_required` with `ha_version`;
  2. client sends `auth` with the LLAT;
  3. server sends `auth_ok` or `auth_invalid`.
- First command after auth is `supported_features` with `features.coalesce_messages = 1`.
- Every command phase message has a monotonically increasing integer `id`; `result.id` routes to one pending request.
- `call_service` sends `domain`, `service`, `target`, `service_data`; the success `result.context.id` is captured for activity logs.
- `get_states`, `get_services`, `get_config` are non-admin baseline commands used for verification and picker fallback.
- Registry commands used when authorized:
  - `config/area_registry/list`
  - `config/floor_registry/list`
  - `config/label_registry/list`
  - `config/device_registry/list`
  - `config/entity_registry/list_for_display`
- `list_for_display` is treated as compressed and fixtures use `ei` (entity id), `di` (device id), `ai` (area id), `en` (entity name). Unknown keys are ignored.
- Targeted live state uses `subscribe_entities` and compressed events:
  - `a` add/full state with `s`, `a`, `lc`, `lu`;
  - `c` change with `+` merges and `-` attribute removals;
  - `r` removes.
- Unsubscribe uses `unsubscribe_events` with the original subscription id.
- JSON `ping` commands are used as the keepalive; missing result within the ping timeout forces reconnect.

## Admin-only / privileged commands

These registry commands can return `unauthorized` for non-admin users and must degrade to `get_states` + `friendly_name` with no area grouping:

- `config/area_registry/list`
- `config/floor_registry/list`
- `config/label_registry/list`
- `config/device_registry/list`
- `config/entity_registry/list_for_display`
- registry invalidation subscriptions for `entity_registry_updated`, `device_registry_updated`, `area_registry_updated`

Flick never writes registries and never calls admin mutation commands.
